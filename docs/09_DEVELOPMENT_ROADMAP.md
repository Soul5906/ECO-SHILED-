# 9. Development Roadmap

## Phase 1 — Run the supplied prototype
- Install dependencies.
- Start backend and frontend.
- Verify scenarios, analysis, reports and exports.
- Run the starter tests.

## Phase 2 — Improve maintainability
- Split frontend pages and components.
- Add typed API client functions.
- Split backend routes, schemas, services, algorithms and persistence.
- Add linting and formatting.

## Phase 3 — Improve analysis quality
- Expand data-quality rules.
- Add more anomaly detectors.
- Add baseline comparison and peer-inverter analysis.
- Version rules and thresholds.
- Add scenario-specific expected test assertions.
- Validate on representative labelled datasets with domain experts.

## Phase 4 — Improve user workflow
- Add dataset registry and metadata.
- Add advanced filters and report comparison.
- Add configurable thresholds.
- Add user access controls if multiple users are needed.

## Phase 5 — Prepare deployment
- Add authentication and authorization.
- Use PostgreSQL where appropriate.
- Add migrations, backups, monitoring and rate limiting.
- Configure HTTPS and deployment secrets.
- Run security, integration and performance tests.

## Definition of done
For every new feature, document:
- User-facing behavior.
- API contract.
- Data model changes.
- Failure modes.
- Tests.
- Known limitations.
